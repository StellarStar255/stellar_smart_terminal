本次完善 SSH 端口转发的状态恢复、异常处理与操作体验，新增手动连通性检测。现有主机、规则和端口组合配置保持兼容。

This release improves SSH forwarding state recovery, error handling, and controls, and adds manual connectivity diagnostics. Existing hosts, forwarding rules, and port groups remain compatible.

## 状态与恢复 / State and recovery

- 打开管理窗口或刷新时核对主连接及监听状态；本应用创建的转发记录与对应主连接绑定，应用重开后可恢复状态。无法确认的规则明确显示“状态待确认”。
- Opening the dialog or refreshing checks the master and listeners. Records tied to the corresponding master restore forwarding state after reopening the app; unverified rules show Unknown status.
- 窗口显示期间每 15 秒在后台检查状态，不自动重连或启停。后台检查不阻塞操作，过期结果不会覆盖新操作，检查失败不会反复弹窗。
- While visible, the dialog checks status every 15 seconds without reconnecting or starting/stopping forwards. Checks keep controls available, discard stale results, and avoid repeated error popups.
- 恢复操作只撤销本应用在当前主连接上记录的同一条规则，不再按进程名结束其他 SSH 进程或重建整条主连接。
- Recovery only cancels this app’s recorded rule on its current master. It no longer kills other SSH processes by name or rebuilds the master connection.

## 启停与错误提示 / Controls and errors

- 新增一键重启，以及启动中、停止中、运行中和失败状态。操作期间阻止重复操作；停止失败则不继续启动。
- Adds Restart and clear starting, stopping, running, and failed states. Repeated operations are blocked while work is in progress; a failed stop prevents a subsequent start.
- SSH 明确确认规则已不存在时，停止视为成功，重启和删除可以继续；兼容真实 OpenSSH 的错误前缀，其他撤销错误仍保留。
- An explicit SSH confirmation that a rule is already absent counts as a successful stop, allowing restart or deletion to continue. Actual OpenSSH diagnostic prefixes are supported without hiding other cancellation errors.
- 区分端口占用、权限、绑定地址、DNS 和超时错误；坏规则单独显示原因，不影响其他规则检查、批量操作或自动挂载。
- Distinguishes port conflicts, permissions, bind addresses, DNS, and timeouts. Invalid rules are reported individually without blocking healthy rules, batch operations, or automatic forwarding.

## 手动连通性检测 / Manual connectivity diagnostics

- 选中规则后点击“测试连通性”，分别查看转发状态、监听连接和目标 TCP 结果。本地转发从 SSH 主机检测目标，远程转发从本机检测目标。
- Select a rule and choose Test Connection to inspect forwarding state, listener connectivity, and destination TCP separately. Local forwards check the destination from the SSH host; remote forwards check it from this computer.
- SOCKS5 需输入明确的目标主机和端口，检测握手及 CONNECT 路径。远端无法执行检测时显示“无法确认”，不会误报目标故障。
- SOCKS5 requires an explicit destination host and port and tests the handshake and CONNECT path. Unavailable remote probes are reported as unverified rather than as destination failures.
- 检测仅验证 TCP/SOCKS5 可连接性，不代表业务、HTTP 响应或登录正常，不自动启停转发或重新认证。
- Diagnostics check TCP/SOCKS5 reachability, not application behavior, HTTP responses, or login. They do not start/stop forwards or authenticate again.

## 验证 / Validation

- 新增隔离的真实 OpenSSH 测试，覆盖三类转发流量、连续停启、应用进程重开、断线恢复、外部监听保护和目标服务正常/关闭场景，并接入 Linux CI。
- Adds isolated real OpenSSH tests covering all three forward types, repeated restarts, application-process reopening, master loss and replacement, preservation of external listeners, and reachable/unreachable destinations, wired into Linux CI.
